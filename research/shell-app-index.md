# Shell APIs for app enumeration, launch, and icons (Windows C++)

Research ticket: wayfinder #5 — "Which shell APIs enumerate, launch and icon-load apps, including UWP?"
Scope: facts needed for AGENTS.md section 6 (app index: AppsFolder + Start Menu `.lnk` sources, dedupe by target, launch, lazy icons, refresh).

Sources are first-party only: Microsoft Learn (`learn.microsoft.com`) and Microsoft Open Specifications. No blog posts, Q&A sites, or third-party write-ups were used as authority. Every factual bullet ends with the source URL that supports it. Claims that first-party sources do not establish are marked **UNVERIFIED** rather than presented as fact.

## 1. Enumerating the shell AppsFolder (`shell:AppsFolder`) from C++

- `shell:AppsFolder` corresponds to the known folder `FOLDERID_AppsFolder`, GUID **`{1e87508d-89c2-42f0-8a7e-645a0f50ca58}`**, display name "Applications", folder type **VIRTUAL**, introduced in Windows 8, with no CSIDL equivalent and no filesystem path. — https://learn.microsoft.com/en-us/windows/win32/shell/knownfolderid
- `SHGetKnownFolderItem(REFKNOWNFOLDERID rfid, KNOWN_FOLDER_FLAG flags, HANDLE hToken, REFIID riid, void **ppv)` retrieves an `IShellItem` for a known folder; `riid` is usually `IID_IShellItem` or `IID_IShellItem2`. — https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shgetknownfolderitem
- **Documented conflict:** the same `SHGetKnownFolderItem` page states "This function cannot be called on folders of type `KF_CATEGORY_FIXED` and `KF_CATEGORY_VIRTUAL`." `FOLDERID_AppsFolder` is explicitly typed VIRTUAL, so the first-party docs do not sanction using `SHGetKnownFolderItem` for it. No first-party page found that resolves this contradiction. — https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shgetknownfolderitem
- `SHGetSpecialFolderLocation` is marked unsupported ("may be altered or unavailable in the future"); its replacement is `SHGetFolderLocation`, which since Windows Vista is a wrapper for `SHGetKnownFolderIDList`. — https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shgetspecialfolderlocation and https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shgetfolderlocation and https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shgetknownfolderidlist
- `IShellFolder::EnumObjects(HWND hwnd, SHCONTF grfFlags, IEnumIDList **ppenumIDList)` creates the folder enumerator. `S_OK` means a valid enumerator was returned; `S_FALSE` means no matching children and `*ppenumIDList` is `NULL`; calling applications must handle both success cases. — https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishellfolder-enumobjects
- `IEnumIDList` exposes `Next`, `Skip`, `Reset`, and `Clone` for walking the child PIDLs returned by `EnumObjects`; the caller frees each PIDL returned by `Next`. — https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-ienumidlist and https://learn.microsoft.com/en-us/windows/win32/shell/folder-info
- A folder's `IShellFolder` is obtained from the desktop root via `SHGetDesktopFolder`, then `IShellFolder::BindToObject` with a folder PIDL, or from a path via `IShellFolder::ParseDisplayName` followed by `BindToObject`. — https://learn.microsoft.com/en-us/windows/win32/shell/folder-info
- Display names come from `IShellFolder::GetDisplayNameOf(PCUITEMID_CHILD pidl, SHGDNF uFlags, STRRET *pName)`, with `StrRetToBuf`/`StrRetToStr` for extraction; the docs note that parsing names for virtual folders can be strings such as `::{GUID}`. — https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishellfolder-getdisplaynameof and https://learn.microsoft.com/en-us/windows/win32/shell/folder-info
- The user-facing display-name property is `PKEY_ItemNameDisplay` (`System.ItemNameDisplay`), formatID **`{B725F130-47EF-101A-A5F1-02608C9EEBAC}`**, propID **10**, type String. — https://learn.microsoft.com/en-us/windows/win32/properties/props-system-itemnamedisplay
- App identity property: `PKEY_AppUserModel_ID` (`System.AppUserModel.ID`), formatID **`{9F4C2855-9F79-4B39-A8D0-E1D42DE1D5F3}`**, propID **5**, type String. — https://learn.microsoft.com/en-us/windows/win32/properties/props-system-appusermodel-id
- `PKEY_AppUserModel_IsDestListSeparator` (`System.AppUserModel.IsDestListSeparator`), formatID **`{9F4C2855-9F79-4B39-A8D0-E1D42DE1D5F3}`**, propID **6**, type Boolean, is a Jump List Tasks separator marker, not an app-identity key. — https://learn.microsoft.com/en-us/windows/win32/properties/props-system-appusermodel-isdestlistseparator
- A first-party PowerShell example enumerates the Start-menu apps namespace via `Shell.Application.NameSpace('shell:::{4234d49b-0245-4df3-b780-3893943456e1}').Items()` and reads each item's `.path` as its AUMID. — https://learn.microsoft.com/en-us/windows/configuration/store/find-aumid
- **UNVERIFIED:** that first-party page uses GUID `{4234d49b-0245-4df3-b780-3893943456e1}` but does not name it `CLSID_AppsFolder`. No first-party page found that assigns a symbolic name to this GUID or equates it with `FOLDERID_AppsFolder` (`{1e87508d-...}`). The relationship between the two GUIDs is not established by the cited sources. — https://learn.microsoft.com/en-us/windows/configuration/store/find-aumid

## 2. Start Menu `.lnk` parsing with `IShellLinkW` (user and all-users)

- `IShellLinkW` inherits `IUnknown` and exposes `GetPath`, `GetIDList`, `GetArguments`, `GetWorkingDirectory`, `GetDescription`, `GetIconLocation`, `GetShowCmd`, `GetHotkey`, `Resolve`, and their setters. — https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-ishelllinkw
- The documented COM pattern is `CoCreateInstance(CLSID_ShellLink, NULL, CLSCTX_INPROC_SERVER, IID_IShellLink, ...)`, then `QueryInterface(IID_IPersistFile, ...)`; the `ResolveIt` sample calls `ppf->Load(wsz, STGM_READ)` before `GetPath`/`GetDescription`. — https://learn.microsoft.com/en-us/windows/win32/shell/links
- `CLSID_ShellLink` / the `.lnk` `LinkCLSID` value is **`{00021401-0000-0000-C000-000000000046}`**; the MS-SHLLINK specification states `LinkCLSID` "MUST be 00021401-0000-0000-C000-000000000046". — https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-shllink/c3376b21-0931-45e4-b2fc-a48ac0e60d15
- Interface IDs: **`IID_IShellLinkA = {000214EE-0000-0000-C000-000000000046}`**, **`IID_IShellLinkW = {000214F9-0000-0000-C000-000000000046}`**. — https://learn.microsoft.com/en-us/windows/win32/shell/reg-shell-exts
- `IPersistFile::Load(LPCOLESTR pszFileName, DWORD dwMode)` opens the file and initializes the object; `dwMode` values come from `STGM`, and `0` means implementation-default permissions. — https://learn.microsoft.com/en-us/windows/win32/api/objidl/nf-objidl-ipersistfile-load
- `IShellLinkW::GetPath(LPWSTR pszFile, int cch, WIN32_FIND_DATAW *pfd, DWORD fFlags)` returns `S_FALSE` with an empty buffer when no path was retrieved; the maximum returned path is `MAX_PATH`. — https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishelllinkw-getpath
- `SLGP_` flags are documented on the `GetPath` page: `SLGP_SHORTPATH` (8.3 name), `SLGP_UNCPRIORITY` ("Unsupported; do not use"), `SLGP_RAWPATH` (may contain unexpanded environment variables), `SLGP_RELATIVEPRIORITY` (Windows Vista+, relative to a prior `SetRelativePath`). — https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishelllinkw-getpath
- `IShellLinkW::GetIDList(PIDLIST_ABSOLUTE *ppidl)` returns the target's absolute PIDL, or `S_FALSE` with `*ppidl == NULL` if none is stored. — https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishelllinkw-getidlist
- `IShellLinkW::GetArguments(LPWSTR pszArgs, int cch)` can truncate silently; on Windows 7 and later, the docs recommend `IPropertyStore` with `PKEY_Link_Arguments` instead. — https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishelllinkw-getarguments
- `IShellLinkW::GetWorkingDirectory(LPWSTR pszDir, int cch)` truncates if the buffer is too small. — https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishelllinkw-getworkingdirectory
- `IShellLinkW::GetDescription(LPWSTR pszName, int cch)` returns at most `INFOTIPSIZE` characters on Windows 2000 and later. — https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishelllinkw-getdescription
- Per-user and all-users Start Menu known folders: `FOLDERID_StartMenu` = **`{625B53C3-AB48-4EC1-BA1F-A1EF4146FC19}`** (`%APPDATA%\Microsoft\Windows\Start Menu`), `FOLDERID_Programs` = **`{A77F5D77-2E2B-44C3-A6A2-ABA601054A51}`** (`%APPDATA%\Microsoft\Windows\Start Menu\Programs`), `FOLDERID_CommonStartMenu` = **`{A4115719-D62E-491D-AA7C-E74B8BE3B067}`** (`%ALLUSERSPROFILE%\Microsoft\Windows\Start Menu`), `FOLDERID_CommonPrograms` = **`{0139D44E-6AFE-49F2-8690-3DAFCAE6FFB8}`** (`%ALLUSERSPROFILE%\Microsoft\Windows\Start Menu\Programs`). — https://learn.microsoft.com/en-us/windows/win32/shell/knownfolderid
- `SHGetKnownFolderPath(REFKNOWNFOLDERID rfid, DWORD dwFlags, HANDLE hToken, PWSTR *ppszPath)` returns a `CoTaskMemFree`-owned Unicode string with no trailing backslash, and returns `E_FAIL` for a `KF_CATEGORY_VIRTUAL` folder. — https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shgetknownfolderpath
- For new code, Microsoft says to use `SHGetKnownFolderPath` with `KNOWNFOLDERID` constants; `CoInitializeEx` must be called on the calling thread and the returned string freed with `CoTaskMemFree`. — https://learn.microsoft.com/en-us/windows/win32/shell/known-folders

## 3. A stable dedupe key across AppsFolder and `.lnk` sources

- An AppUserModelID (AUMID) associates processes, files, and windows with an application; explicit IDs are optional, and "Applications cannot retrieve a system-assigned AppUserModelID" — an AUMID key therefore only exists when the application declared one. — https://learn.microsoft.com/en-us/windows/win32/shell/appids
- An application-defined AUMID has the form `CompanyName.ProductName.SubProduct.VersionInformation`, at most 128 characters, no spaces, pascal-cased. — https://learn.microsoft.com/en-us/windows/win32/shell/appids
- A shortcut (an `IShellLink`, `CLSID_ShellLink`, or `.lnk` file) supports properties through `IPropertyStore`, and `System.AppUserModel.ID` should be applied to the shortcut when it is created — this is the first-party basis for an AUMID stored on a `.lnk`. — https://learn.microsoft.com/en-us/windows/win32/shell/appids
- `PKEY_AppUserModel_ID` is formatID **`{9F4C2855-9F79-4B39-A8D0-E1D42DE1D5F3}`**, propID **5**, type String. — https://learn.microsoft.com/en-us/windows/win32/properties/props-system-appusermodel-id
- `SHGetPropertyStoreFromIDList(PCIDLIST_ABSOLUTE pidl, GETPROPERTYSTOREFLAGS flags, REFIID riid, void **ppv)` retrieves an `IPropertyStore` (or related interface) from an absolute PIDL. — https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-shgetpropertystorefromidlist
- `IShellItem2::GetPropertyStore(GETPROPERTYSTOREFLAGS flags, REFIID riid, void **ppv)` is the equivalent when an `IShellItem2` is already held; the file stays open for the lifetime of the property store. — https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishellitem2-getpropertystore
- `IPropertyStore::GetValue(REFPROPERTYKEY key, PROPVARIANT *pv)` returns `S_OK` with `vt == VT_EMPTY` when the property is absent, so a missing AUMID is a normal case, not an error. — https://learn.microsoft.com/en-us/windows/win32/api/propsys/nf-propsys-ipropertystore-getvalue
- For packaged apps, the AUMID is `PackageFamilyName + "!" + ApplicationId` from the manifest's `<Application Id="...">`; the first-party document gives this exact construction. — https://learn.microsoft.com/en-us/windows/configuration/store/find-aumid
- `AppListEntry.AppUserModelId` is documented as based on the package family name plus the Package Relative Application ID (PRAID), independent of package version and architecture. — https://learn.microsoft.com/en-us/uwp/api/windows.applicationmodel.core.applistentry.appusermodelid
- **UNVERIFIED:** no first-party page found that explicitly states AppsFolder items expose `PKEY_AppUserModel_ID` through `IPropertyStore`. The closest first-party evidence is the "Choose Details → AppUserModelId" column on `shell:Appsfolder` and the general shortcut-property documentation. — https://learn.microsoft.com/en-us/windows/configuration/store/find-aumid and https://learn.microsoft.com/en-us/windows/win32/shell/appids
- **UNVERIFIED:** no first-party source endorses "target path + arguments" as a deduplication key. Those individual fields are documented (`GetPath`, `GetArguments`, `SHELLEXECUTEINFOW::lpFile`/`lpParameters`), but a dedup strategy is an application decision, not a documented Microsoft API behavior. — https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishelllinkw-getpath and https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ns-shellapi-shellexecuteinfow

## 4. UWP / packaged app activation

- `IApplicationActivationManager::ActivateApplication(LPCWSTR appUserModelId, LPCWSTR arguments, ACTIVATEOPTIONS options, DWORD *processId)` activates the specified Windows Store app for the generic `Windows.Launch` contract in the current session; `appUserModelId` is documented as "the application user model ID of the Windows Store app." — https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-iapplicationactivationmanager-activateapplication
- `ACTIVATEOPTIONS` values from that page: `AO_NONE` = `0x00000000`, `AO_DESIGNMODE` = `0x00000001`, `AO_NOERRORUI` = `0x00000002`, `AO_NOSPLASHSCREEN` = `0x00000004`, `AO_PRELAUNCH` = `0x2000000` (Windows 10 and later). — https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-iapplicationactivationmanager-activateapplication
- `AO_DESIGNMODE` and `AO_NOSPLASHSCREEN` require `IPackageDebugSettings::EnableDebugging` on the package; without debug mode, `AO_NOSPLASHSCREEN` causes PLM to terminate the app after a few seconds. — https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-iapplicationactivationmanager-activateapplication
- An `IApplicationActivationManager` is obtained with `CoCreateInstance(CLSID_ApplicationActivationManager, ...)`; a long-lived calling process may create it in-proc, while a short-lived launcher should use `CLSCTX_LOCAL_SERVER` so the object lives in a Dllhost.exe instance. — https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-iapplicationactivationmanager
- For packaged applications, the AUMID is declared in the manifest's `Application` element and derived from the package family name plus the declared application ID. — https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/package-identity-overview
- `IAppxManifestApplication::GetAppUserModelId(LPWSTR *appUserModelId)` reads the AUMID from a package manifest; the caller frees the result with `CoTaskMemFree`. — https://learn.microsoft.com/en-us/windows/win32/api/appxpackaging/nf-appxpackaging-iappxmanifestapplication-getappusermodelid
- First-party AUMID discovery methods: `Get-StartApps`, `Get-AppxPackage` plus manifest `application.id`, the `HKCU\Software\Classes\ActivatableClasses\Package` registry key, and Explorer's `shell:Appsfolder` "AppUserModelId" detail column. — https://learn.microsoft.com/en-us/windows/configuration/store/find-aumid
- **UNVERIFIED:** no first-party end-to-end C++ sample found that takes a packaged app's AUMID from an AppsFolder `IShellItem` property store and passes it directly to `ActivateApplication`; the two halves are documented separately. — https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-shgetpropertystorefromidlist and https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-iapplicationactivationmanager-activateapplication

## 5. Win32 launch with `ShellExecuteEx`

- `ShellExecuteExW(SHELLEXECUTEINFOW *pExecInfo)` returns `BOOL`; on failure, `GetLastError` provides extended information. — https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shellexecuteexw
- COM should be initialized before `ShellExecuteEx` because execution can be delegated to COM-based Shell extensions; the docs recommend `CoInitializeEx(NULL, COINIT_APARTMENTTHREADED | COINIT_DISABLE_OLE1DDE)`. — https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shellexecuteexw
- `SHELLEXECUTEINFOW` fields: `cbSize`, `fMask`, `hwnd`, `lpVerb`, `lpFile`, `lpParameters`, `lpDirectory`, `nShow`, `hInstApp`, `lpIDList`, `lpClass`, `hkeyClass`, `dwHotKey`, `hIcon`/`hMonitor`, `hProcess`. — https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ns-shellapi-shellexecuteinfow
- `lpVerb` may be `NULL` (default verb, else `"open"`); documented verbs include `open`, `edit`, `explore`, `find`, `print`, `properties`, `openas`, and `runas` (elevates via UAC). — https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ns-shellapi-shellexecuteinfow
- `lpFile` names the file/object, `lpParameters` holds space-separated arguments and should be `NULL` for a document file, and `lpDirectory` sets the working directory. — https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ns-shellapi-shellexecuteinfow
- `lpIDList` is an absolute `ITEMIDLIST` and is ignored unless `fMask` includes `SEE_MASK_IDLIST` (`0x00000004`) or `SEE_MASK_INVOKEIDLIST` (`0x0000000C`); `SEE_MASK_INVOKEIDLIST` overrides and implies `SEE_MASK_IDLIST`, and either `lpFile` or `lpIDList` may identify the item. — https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ns-shellapi-shellexecuteinfow
- `SEE_MASK_FLAG_LOG_USAGE` (`0x04000000`) indicates a user-initiated launch and enables tracking of frequently used programs; `SEE_MASK_NOASYNC` is required when the calling thread has no message loop or will exit soon. — https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ns-shellapi-shellexecuteinfow
- `hProcess` is populated only when `fMask` includes `SEE_MASK_NOCLOSEPROCESS`, and can still be `NULL` (for example with DDE or `SEE_MASK_INVOKEIDLIST`). — https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ns-shellapi-shellexecuteinfow

## 6. Lazy icon loading

- `IShellItemImageFactory::GetImage(SIZE size, SIIGBF flags, HBITMAP *phbm)` returns an `HBITMAP`; the default behavior loads a thumbnail and falls back to the item's icon, extracting it if not currently cached. — https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishellitemimagefactory-getimage
- `SIIGBF` values (documented on the `GetImage` page): `SIIGBF_RESIZETOFIT` = `0x00000000`, `SIIGBF_BIGGERSIZEOK` = `0x00000001`, `SIIGBF_MEMORYONLY` = `0x00000002`, `SIIGBF_ICONONLY` = `0x00000004`, `SIIGBF_THUMBNAILONLY` = `0x00000008`, `SIIGBF_INCACHEONLY` = `0x00000010`, `SIIGBF_CROPTOSQUARE` = `0x00000020`, `SIIGBF_WIDETHUMBNAILS` = `0x00000040`, `SIIGBF_ICONBACKGROUND` = `0x00000080`, `SIIGBF_SCALEUP` = `0x00000100`. — https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishellitemimagefactory-getimage
- `SIIGBF_THUMBNAILONLY` fails for items without a thumbnail; `SIIGBF_BIGGERSIZEOK` lets the caller stretch a larger cached image itself; `SIIGBF_MEMORYONLY` returns an already-cached icon without disk access. — https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishellitemimagefactory-getimage
- Microsoft states: "Icon extraction can be time consuming. This method generally should not be called from a UI thread"; `SIIGBF_INCACHEONLY` is the only flag that permits a UI-thread call, with a background thread required when the image is not cached. — https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishellitemimagefactory-getimage
- The caller must free the returned `HBITMAP` with `DeleteObject`. — https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishellitemimagefactory-getimage
- A pointer to `IShellItemImageFactory` is commonly obtained via `SHCreateItemFromIDList`, `SHCreateItemFromParsingName`, `SHCreateItemFromRelativeName`, `SHCreateItemInKnownFolder`, or `SHCreateItemWithParent`. — https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-ishellitemimagefactory
- Alternative: `SHGetFileInfoW(LPCWSTR pszPath, DWORD dwFileAttributes, SHFILEINFOW *psfi, UINT cbFileInfo, UINT uFlags)` with flags including `SHGFI_ICON` (`0x000000100`), `SHGFI_SMALLICON` (`0x000000001`), `SHGFI_SYSICONINDEX` (`0x000004000`), `SHGFI_PIDL` (`0x000000008`), and `SHGFI_DISPLAYNAME` (`0x000000200`). — https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shgetfileinfow
- `SHGetFileInfo` should be called from a background thread to avoid UI stalls, requires COM initialization (`CoInitialize`/`OleInitialize`), and any returned `hIcon` must be freed with `DestroyIcon`. — https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shgetfileinfow
- **UNVERIFIED:** no standalone first-party enum page for `SIIGBF` was found; the flag definitions above are from the `GetImage` method page. — https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishellitemimagefactory-getimage

## 7. Refresh with `ReadDirectoryChangesW`

- `ReadDirectoryChangesW(HANDLE hDirectory, LPVOID lpBuffer, DWORD nBufferLength, BOOL bWatchSubtree, DWORD dwNotifyFilter, LPDWORD lpBytesReturned, LPOVERLAPPED lpOverlapped, LPOVERLAPPED_COMPLETION_ROUTINE lpCompletionRoutine)` retrieves descriptions of changes within a directory; it does not report changes to the directory itself. — https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-readdirectorychangesw
- `hDirectory` must be opened with `FILE_LIST_DIRECTORY` (or a right such as `GENERIC_READ` that includes it); the docs direct callers to `CreateFile` with `FILE_FLAG_BACKUP_SEMANTICS`. — https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-readdirectorychangesw
- `bWatchSubtree == TRUE` monitors the directory tree rooted at the handle; `FALSE` monitors only the specified directory. — https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-readdirectorychangesw
- `dwNotifyFilter` values: `FILE_NOTIFY_CHANGE_FILE_NAME` `0x00000001`, `FILE_NOTIFY_CHANGE_DIR_NAME` `0x00000002`, `FILE_NOTIFY_CHANGE_ATTRIBUTES` `0x00000004`, `FILE_NOTIFY_CHANGE_SIZE` `0x00000008`, `FILE_NOTIFY_CHANGE_LAST_WRITE` `0x00000010`, `FILE_NOTIFY_CHANGE_LAST_ACCESS` `0x00000020`, `FILE_NOTIFY_CHANGE_CREATION` `0x00000040`, `FILE_NOTIFY_CHANGE_SECURITY` `0x00000100`. — https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-readdirectorychangesw
- Asynchronous completion is received through `GetOverlappedResult`, `GetQueuedCompletionStatus` (after `CreateIoCompletionPort`), or an `LPOVERLAPPED_COMPLETION_ROUTINE`. The buffer must be DWORD-aligned; a buffer larger than 64 KB over a network fails with `ERROR_INVALID_PARAMETER`. — https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-readdirectorychangesw
- On buffer overflow the call still returns nonzero, but the entire buffer is discarded and `lpBytesReturned` is zero; `ERROR_NOTIFY_ENUM_DIR` means the application should re-enumerate the directory or subtree. — https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-readdirectorychangesw
- `FILE_NOTIFY_INFORMATION` is `{ DWORD NextEntryOffset; DWORD Action; DWORD FileNameLength; WCHAR FileName[1]; }`; `NextEntryOffset == 0` marks the last record, `FileNameLength` is in bytes and excludes the terminator, and `FileName` is UTF-16, relative to the directory handle, and not null-terminated. — https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-file_notify_information
- `Action` values: `FILE_ACTION_ADDED` `0x00000001`, `FILE_ACTION_REMOVED` `0x00000002`, `FILE_ACTION_MODIFIED` `0x00000003`, `FILE_ACTION_RENAMED_OLD_NAME` `0x00000004`, `FILE_ACTION_RENAMED_NEW_NAME` `0x00000005`. — https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-file_notify_information
- **UNVERIFIED:** no standalone first-party enum page for `FILE_ACTION` was found; the values above are from the `FILE_NOTIFY_INFORMATION` page.
