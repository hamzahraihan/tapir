# Backdrop, corners, and high-contrast fallback on Windows 10 and 11

Research ticket: wayfinder #2 ("What backdrop, corners and high-contrast fallback actually work on Windows 10 and 11?"). Scope: facts only, from first-party sources (Microsoft Learn reference pages generated from the Windows SDK headers and the Microsoft design docs). No design recommendations are made here. Every factual claim carries its source URL inline.

## 1. `DWMWA_SYSTEMBACKDROP_TYPE`: values and Windows-version support

- `DWMWA_SYSTEMBACKDROP_TYPE` and `DWMWA_WINDOW_CORNER_PREFERENCE` are members of the `DWMWINDOWATTRIBUTE` enumeration; `DWMWA_WINDOW_CORNER_PREFERENCE` has the numeric value 33. ([DWMWINDOWATTRIBUTE (dwmapi.h)](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute))
- `DWMWA_SYSTEMBACKDROP_TYPE` can be used with both `DwmGetWindowAttribute` and `DwmSetWindowAttribute`; `pvAttribute` points to a `DWM_SYSTEMBACKDROP_TYPE` value. It is "supported starting with Windows 11 Build 22621." ([DWMWINDOWATTRIBUTE](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute))
- `DWM_SYSTEMBACKDROP_TYPE` defines: `DWMSBT_AUTO` (the default; DWM automatically decides, applies the backdrop only behind the default Win32 title bar, and "might also decide to draw no backdrop material at all"); `DWMSBT_NONE` (no system backdrop); `DWMSBT_MAINWINDOW` (backdrop behind the entire window bounds; on Windows 11 this is Mica in its default variant); `DWMSBT_TRANSIENTWINDOW` (backdrop behind the entire window bounds; on Windows 11 this is Desktop Acrylic, "also known as Background Acrylic, in its brightest variant"); `DWMSBT_TABBEDWINDOW` (on Windows 11, Mica Alt). The enum page states the material "might change with future Windows releases." ([DWM_SYSTEMBACKDROP_TYPE](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwm_systembackdrop_type))
- The `DWM_SYSTEMBACKDROP_TYPE` page lists its minimum supported client as **Windows 11 Build 22621**. ([DWM_SYSTEMBACKDROP_TYPE](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwm_systembackdrop_type))
- The Mica design doc separately states that Mica Alt "is available for apps that use Windows App SDK 1.1 or later, while running on Windows 11 version 22000 or later"; that is a statement about the material, distinct from the DWM attribute's documented 22621 minimum. ([Mica material](https://learn.microsoft.com/en-us/windows/apps/design/style/mica))
- `DwmSetWindowAttribute(hwnd, dwAttribute, pvAttribute, cbAttribute)` returns `S_OK` on success and "an HRESULT error code" otherwise; it returns `DWM_E_COMPOSITIONDISABLED` if desktop composition is disabled (Windows 7 and earlier). ([DwmSetWindowAttribute](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/nf-dwmapi-dwmsetwindowattribute))
- Microsoft documents `DWMWA_USE_HOSTBACKDROPBRUSH`, `DWMWA_USE_IMMERSIVE_DARK_MODE`, `DWMWA_BORDER_COLOR`, `DWMWA_CAPTION_COLOR`, `DWMWA_TEXT_COLOR`, `DWMWA_VISIBLE_FRAME_BORDER_THICKNESS` and `DWMWA_WINDOW_CORNER_PREFERENCE` as "supported starting with Windows 11 Build 22000". No Windows 10 build is listed for any of these values. ([DWMWINDOWATTRIBUTE](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute))
- `DWMWA_REDIRECTIONBITMAP_ALPHA` is "supported starting with Windows 11 Build 26100." If set to true, "the window must contain premultiplied alpha values in each pixel"; if false, "the alpha is ignored and the redirection bitmap is treated as fully opaque." It defaults to false. ([DWMWINDOWATTRIBUTE](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute))

## 2. `DWMWA_WINDOW_CORNER_PREFERENCE`: values and Windows-version support

- `DWMWA_WINDOW_CORNER_PREFERENCE` is set through `DwmSetWindowAttribute` and its `pvAttribute` points to a `DWM_WINDOW_CORNER_PREFERENCE` value. It is "supported starting with Windows 11 Build 22000." ([DWMWINDOWATTRIBUTE](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute))
- The enumeration is `DWMWCP_DEFAULT = 0` ("Let the system decide when to round window corners"), `DWMWCP_DONOTROUND = 1` ("Never round window corners"), `DWMWCP_ROUND = 2` ("Round the corners, if appropriate"), `DWMWCP_ROUNDSMALL = 3` ("Round the corners if appropriate, with a small radius"). ([DWM_WINDOW_CORNER_PREFERENCE](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwm_window_corner_preference))
- The enum page lists both minimum supported client and minimum supported server as **Windows Build 22000**. ([DWM_WINDOW_CORNER_PREFERENCE](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwm_window_corner_preference))
- `DWMWA_BORDER_COLOR` (also Windows 11 Build 22000) can suppress border drawing: specifying `DWMWA_COLOR_NONE` (0xFFFFFFFE) "will suppress the drawing of the window border. This makes it possible to have a rounded window with no border." ([DWMWINDOWATTRIBUTE](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute))

## 3. High-contrast behaviour and the OS-level solid fallback

- "In High Contrast mode, users continue to see the familiar background color of their choosing in place of Mica or Mica Alt." ([Mica material](https://learn.microsoft.com/en-us/windows/apps/design/style/mica))
- "In High Contrast mode, users continue to see the familiar background color of their choosing in place of acrylic." ([Acrylic material](https://learn.microsoft.com/en-us/windows/apps/design/style/acrylic))
- Mica appears as a solid fallback color — `SolidBackgroundFillColorBase` for Mica, `SolidBackgroundFillColorBaseAlt` for Mica Alt — when transparency is turned off in Settings, Battery Saver is active, the app runs on low-end hardware, an app window deactivates, or the Windows version is below 22000. ([Mica material](https://learn.microsoft.com/en-us/windows/apps/design/style/mica))
- Both background and in-app acrylic appear as a solid color when transparency effects are off, Battery Saver is active, or the app runs on low-end hardware. Background acrylic additionally replaces its translucency and texture with a solid color when the desktop app window deactivates, or when running on Xbox, HoloLens, or in tablet mode. ([Acrylic material](https://learn.microsoft.com/en-us/windows/apps/design/style/acrylic))
- Acrylic rendering "is GPU-intensive, which can increase device power consumption and shorten battery life"; acrylic effects "are automatically disabled when a device enters Battery Saver mode" and users can disable them for all apps via the Transparency effects setting. ([Acrylic material](https://learn.microsoft.com/en-us/windows/apps/design/style/acrylic))
- Mica is opaque and "only samples the desktop wallpaper once to create its visualization", and "fall[s] back to a neutral color when the app is inactive." ([Mica material](https://learn.microsoft.com/en-us/windows/apps/design/style/mica))
- The guidance for transient UI is to use background acrylic for "context menus, flyouts, non-modal popups, or light-dismiss panes." ([Acrylic material](https://learn.microsoft.com/en-us/windows/apps/design/style/acrylic))
- High contrast state is queryable from Win32: `HIGHCONTRASTW.dwFlags` contains `HCF_HIGHCONTRASTON` (0x00000001) when "the high contrast feature is on", and the structure is used with `SystemParametersInfoW` with `SPI_GETHIGHCONTRAST` or `SPI_SETHIGHCONTRAST` (with `cbSize` set when getting). ([HIGHCONTRASTW (winuser.h)](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-highcontrastw))
- For Mica to be visible, Microsoft's layering guidance says to "set the background to transparent for all layers where you want to see Mica so the Mica shows through." ([Mica material](https://learn.microsoft.com/en-us/windows/apps/design/style/mica))
- These high-contrast statements come from Windows App SDK/WinUI design docs describing material-layer policy; the raw Win32 `DwmSetWindowAttribute`/`DWMWINDOWATTRIBUTE` reference pages do not discuss high-contrast behaviour, and no first-party source checked states that `DwmSetWindowAttribute(DWMWA_SYSTEMBACKDROP_TYPE, ...)` itself detects high contrast. ([Mica material](https://learn.microsoft.com/en-us/windows/apps/design/style/mica); [DwmSetWindowAttribute](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/nf-dwmapi-dwmsetwindowattribute))

## 4. When the backdrop cannot be used, and the solid fallback path

- A failed backdrop setup surfaces as a failed `DwmSetWindowAttribute` call, i.e. a non-`S_OK` HRESULT error code; the reference page does not document a dedicated "acrylic failed" HRESULT. ([DwmSetWindowAttribute](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/nf-dwmapi-dwmsetwindowattribute))
- `DWMSBT_NONE` is the explicit "don't draw any system backdrop" value, and `DWMSBT_AUTO` may result in no backdrop at all by DWM heuristic. ([DWM_SYSTEMBACKDROP_TYPE](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwm_systembackdrop_type))
- Windows 10 has no documented support for `DWMWA_SYSTEMBACKDROP_TYPE`, `DWMWA_WINDOW_CORNER_PREFERENCE`, or the other Windows 11 DWM attributes listed above (all are documented as starting with Build 22000 or 22621). ([DWMWINDOWATTRIBUTE](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute))
- The OS-level fallback is a solid color, not a failure state: Mica/Acrylic substitute the user's familiar high-contrast background color or a solid fallback color under the conditions in section 3. ([Mica material](https://learn.microsoft.com/en-us/windows/apps/design/style/mica); [Acrylic material](https://learn.microsoft.com/en-us/windows/apps/design/style/acrylic))
- The system backdrop is drawn "behind the entire window bounds" for the explicit `DWMSBT_*` values, so an app that wants to see it must leave its own content layers transparent. ([DWM_SYSTEMBACKDROP_TYPE](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwm_systembackdrop_type); [Mica material](https://learn.microsoft.com/en-us/windows/apps/design/style/mica))
- In the Windows App SDK path, support is checked explicitly: `MicaController.IsSupported()` and `DesktopAcrylicController.IsSupported();` the docs require system support, a valid target, a `SystemBackdropConfiguration` object, and a `DispatcherQueue`. The controllers expose a `FallbackColor` property (alongside `TintColor`, `TintOpacity`, and `LuminosityOpacity`). ([System backdrops (Mica/Acrylic)](https://learn.microsoft.com/en-us/windows/apps/develop/ui/system-backdrops))
- The Win32 Mica sample registers its window class with `wcex.hbrBackground = (HBRUSH)(COLOR_WINDOW + 1)` and sets a compositor target root before enabling Mica. ([Use Mica material in Win32 apps](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/ui/apply-mica-win32))
- No Microsoft source checked defines an API-level "draw a solid background on HRESULT failure" recipe for raw Win32; the documented solid fallbacks are material-policy behaviour (WinUI theme resources / controller `FallbackColor`), not a documented DWM fallback procedure. ([DwmSetWindowAttribute](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/nf-dwmapi-dwmsetwindowattribute); [System backdrops (Mica/Acrylic)](https://learn.microsoft.com/en-us/windows/apps/develop/ui/system-backdrops))

## 5. DXGI flip-model swap chain and premultiplied alpha

- `DXGI_SWAP_EFFECT` defines `DISCARD = 0`, `SEQUENTIAL = 1`, `FLIP_SEQUENTIAL = 3`, `FLIP_DISCARD = 4`. `FLIP_SEQUENTIAL` is supported in Direct3D 11 starting with Windows 8; `FLIP_DISCARD` starting with Windows 10. ([DXGI_SWAP_EFFECT](https://learn.microsoft.com/en-us/windows/win32/api/dxgi/ne-dxgi-dxgi_swap_effect))
- In the flip model, all back buffers are shared with the DWM, which composes directly from them "without any additional copy operations"; the flip model is described as "the more efficient model." ([DXGI_SWAP_EFFECT](https://learn.microsoft.com/en-us/windows/win32/api/dxgi/ne-dxgi-dxgi_swap_effect); [For best performance, use DXGI flip model](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/for-best-performance--use-dxgi-flip-model))
- `IDXGIFactory2::CreateSwapChainForComposition` creates a swap chain for DirectComposition and requires `DXGI_SWAP_EFFECT_FLIP_SEQUENTIAL` ("supports only flip presentation model") and `DXGI_SCALING_STRETCH`. It states that software drivers, "like `D3D_DRIVER_TYPE_REFERENCE`, are not supported for composition swap chains." ([CreateSwapChainForComposition](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_2/nf-dxgi1_2-idxgifactory2-createswapchainforcomposition))
- Flip-model requirements: buffer count at least 2; `SampleDesc.Count = 1` and `Quality = 0` because MSAA is not supported; allowed formats include `DXGI_FORMAT_B8G8R8A8_UNORM` and `DXGI_FORMAT_R8G8B8A8_UNORM`; one flip-model swap chain per HWND; the back buffer must be re-bound to the immediate context after `Present`. ([DXGI flip model](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/dxgi-flip-model); [For best performance, use DXGI flip model](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/for-best-performance--use-dxgi-flip-model))
- `DXGI_ALPHA_MODE` defines `UNSPECIFIED = 0`, `PREMULTIPLIED = 1`, `STRAIGHT = 2`, `IGNORE = 3`; premultiplied means "each color is first scaled by the alpha value", so typically no color channel exceeds the alpha channel. Minimum supported client: Windows 8 and Platform Update for Windows 7. ([DXGI_ALPHA_MODE](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_2/ne-dxgi1_2-dxgi_alpha_mode))
- For foreground swap chains, Microsoft requires `DXGI_ALPHA_MODE_PREMULTIPLIED` and `DXGI_SCALING_NONE`, and explains that premultiplied alpha means color values are already multiplied by alpha before presentation. ([CreateSwapChainForCoreWindow](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_2/nf-dxgi1_2-idxgifactory2-createswapchainforcorewindow))
- `DXGI_SWAP_CHAIN_DESC1.AlphaMode` identifies the transparency behavior of the swap-chain back buffer. ([DXGI_SWAP_CHAIN_DESC1](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_2/ns-dxgi1_2-dxgi_swap_chain_desc1))
- `DWMWA_REDIRECTIONBITMAP_ALPHA` (Windows 11 Build 26100) is the DWM-side counterpart: when enabled the window must supply premultiplied alpha per pixel; otherwise alpha is ignored and the redirection bitmap is opaque. ([DWMWINDOWATTRIBUTE](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute))
- `DXGI_SWAP_CHAIN_FLAG` includes `GDI_COMPATIBLE = 4`, `FRAME_LATENCY_WAITABLE_OBJECT = 64` (Windows 8.1+), `FOREGROUND_LAYER = 128` (Windows 8.1+, CoreWindow swap chains only) and `ALLOW_TEARING = 2048`, which "requires the use of a DXGI_SWAP_EFFECT_FLIP_* swap effect." ([DXGI_SWAP_CHAIN_FLAG](https://learn.microsoft.com/en-us/windows/win32/api/dxgi/ne-dxgi-dxgi_swap_chain_flag))
- `IDCompositionDevice::CreateSurface` accepts `DXGI_ALPHA_MODE_UNSPECIFIED` (same effect as `IGNORE`), `DXGI_ALPHA_MODE_PREMULTIPLIED` ("color channels contain values that are premultiplied with the alpha channel"), and `DXGI_ALPHA_MODE_IGNORE` ("bitmap should be rendered opaquely"); supported DirectComposition surface formats are `B8G8R8A8_UNORM`, `R8G8B8A8_UNORM`, and `R16G16B16A16_FLOAT`. ([IDCompositionDevice::CreateSurface](https://learn.microsoft.com/en-us/windows/win32/api/dcomp/nf-dcomp-idcompositiondevice-createsurface))
- No blanket rule that every composition-targeted swap chain must use premultiplied alpha was found in the sources checked: the explicit requirement is for foreground layers, while `DXGI_SWAP_CHAIN_DESC1.AlphaMode` is a choice and DirectComposition surfaces accept `IGNORE`. ([CreateSwapChainForCoreWindow](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_2/nf-dxgi1_2-idxgifactory2-createswapchainforcorewindow); [DXGI_SWAP_CHAIN_DESC1](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_2/ns-dxgi1_2-dxgi_swap_chain_desc1); [IDCompositionDevice::CreateSurface](https://learn.microsoft.com/en-us/windows/win32/api/dcomp/nf-dcomp-idcompositiondevice-createsurface))

## 6. `WS_EX_NOREDIRECTIONBITMAP`

- `WS_EX_NOREDIRECTIONBITMAP` has value `0x00200000L` and is documented as: "The window does not render to a redirection surface. This is for windows that do not have visible content or that use mechanisms other than surfaces to provide their visual." ([Extended Window Styles](https://learn.microsoft.com/en-us/windows/win32/winmsg/extended-window-styles))
- `WS_EX_TOOLWINDOW` (`0x00000080L`) gives a shorter title bar and keeps the window out of the taskbar and the ALT+TAB dialog. ([Extended Window Styles](https://learn.microsoft.com/en-us/windows/win32/winmsg/extended-window-styles))
- A composition target window is allowed to be a layered window (`WS_EX_LAYERED`); the visual tree must be bound to a window before anything can be displayed. ([CreateTargetForHwnd](https://learn.microsoft.com/en-us/windows/win32/api/dcomp/nf-dcomp-idcompositiondevice-createtargetforhwnd))
- A first-party archived MSDN Magazine article states: "As of Windows 8, you can now create a top-level window and request that it be created without a redirection surface… you need to use the WS_EX_NOREDIRECTIONBITMAP extended window style that tells the composition engine not to allocate a redirection surface for the window." The API reference itself does not literally name DirectComposition, but says "mechanisms other than surfaces to provide their visual." ([High-Performance Window Layering Using the Windows Composition Engine](https://learn.microsoft.com/en-us/archive/msdn-magazine/2014/june/windows-with-c-high-performance-window-layering-using-the-windows-composition-engine); [Extended Window Styles](https://learn.microsoft.com/en-us/windows/win32/winmsg/extended-window-styles))

## 7. DirectComposition visual attachment

- "An application must use the `IDCompositionDesktopDevice` interface in order to use DirectComposition in a Win32 desktop application. This interface allows the application to connect a visual tree to a window and to host layered child windows for composition." Minimum supported client: Windows 8.1. ([IDCompositionDesktopDevice](https://learn.microsoft.com/en-us/windows/win32/api/dcomp/nn-dcomp-idcompositiondesktopdevice))
- `CreateTargetForHwnd(hwnd, topmost, &target)` creates a composition target bound to the window; "a DirectComposition visual tree must be bound to a window before anything can be displayed on screen"; the window must belong to the calling process and at most two targets (one topmost, one not) can be created per window. ([CreateTargetForHwnd](https://learn.microsoft.com/en-us/windows/win32/api/dcomp/nf-dcomp-idcompositiondevice-createtargetforhwnd))
- `IDCompositionTarget::SetRoot(visual)` sets the root visual of the visual tree; passing `NULL` leaves the tree empty. Minimum supported client: Windows 8. ([IDCompositionTarget::SetRoot](https://learn.microsoft.com/en-us/windows/win32/api/dcomp/nf-dcomp-idcompositiontarget-setroot))
- `IDCompositionVisual::SetContent` accepts an `IDCompositionSurface`, an `IDXGISwapChain1`, or a wrapper from `CreateSurfaceFromHandle`/`CreateSurfaceFromHwnd`. ([IDCompositionVisual::SetContent](https://learn.microsoft.com/en-us/windows/win32/api/dcomp/nf-dcomp-idcompositionvisual-setcontent))
- For DirectComposition, the documented chain is `CreateSwapChainForComposition` → `IDCompositionVisual::SetContent` (swap chain as visual content) → bind the visual into the visual tree. ([CreateSwapChainForComposition](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_2/nf-dxgi1_2-idxgifactory2-createswapchainforcomposition))
- Initialization uses `DCompositionCreateDevice` with the device's DXGI interface, then `CreateTargetForHwnd`, `CreateVisual`, `SetContent`, `SetRoot`, and `IDCompositionDevice::Commit` to batch the composition commands. ([How to initialize DirectComposition](https://learn.microsoft.com/en-us/windows/win32/directcomp/initialize-directcomposition); [IDCompositionVisual::SetContent](https://learn.microsoft.com/en-us/windows/win32/api/dcomp/nf-dcomp-idcompositionvisual-setcontent))
- DirectComposition content is composed on top of whatever is drawn directly to the window through `GetDC` or DirectX `Present` calls. ([CreateTargetForHwnd](https://learn.microsoft.com/en-us/windows/win32/api/dcomp/nf-dcomp-idcompositiondevice-createtargetforhwnd))
- The documented Win32 method names are `IDCompositionTarget::SetRoot` and `IDCompositionDevice::CreateTargetForHwnd` (or `IDCompositionDesktopDevice::CreateTargetForHwnd`); there are no Win32 DirectComposition APIs named `SetRootVisual` or `CreateTargetForWindow`. ([IDCompositionTarget::SetRoot](https://learn.microsoft.com/en-us/windows/win32/api/dcomp/nf-dcomp-idcompositiontarget-setroot); [CreateTargetForHwnd](https://learn.microsoft.com/en-us/windows/win32/api/dcomp/nf-dcomp-idcompositiondevice-createtargetforhwnd))
- Microsoft notes: "For apps on Windows 10, we recommend using Windows.UI.Composition APIs instead of DirectComposition." ([How to use DirectComposition](https://learn.microsoft.com/en-us/windows/win32/directcomp/how-to-use-directcomposition))

## 8. `IDXGIDevice3::Trim` on hide

- `IDXGIDevice3::Trim()` "trims the graphics memory allocated by the IDXGIDevice3 DXGI device on the app's behalf"; graphics drivers periodically allocate internal memory buffers that count against the app's memory usage. ([IDXGIDevice3::Trim](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_3/nf-dxgi1_3-idxgidevice3-trim))
- "Starting in Windows 8.1, apps that render with Direct2D and/or Direct3D ... must call **Trim** in response to the PLM suspend callback. The Direct3D runtime and the graphics driver will discard internal memory buffers allocated for the app, reducing its memory footprint." ([IDXGIDevice3::Trim](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_3/nf-dxgi1_3-idxgidevice3-trim))
- Calling `Trim` "does not change the rendering state of the graphics device and it has no effect on rendering operations"; there is "a brief performance hit when internal buffers are reallocated during the first rendering operations after the **Trim** call", so "apps should only call **Trim** when going idle for a period of time". ([IDXGIDevice3::Trim](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_3/nf-dxgi1_3-idxgidevice3-trim))
- Microsoft advises calling `Trim` as one of the last D3D operations before going idle, calling `ID3D11DeviceContext::ClearState` first, and releasing middleware references first; because Direct3D defers destruction, releasing the final reference after `Trim` is not guaranteed to deallocate memory before suspension. Minimum supported client: Windows 8.1. ([IDXGIDevice3::Trim](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_3/nf-dxgi1_3-idxgidevice3-trim))
- The explicitly documented trigger is the PLM suspend callback (a UWP concept) and, generally, "going idle for a period of time"; Microsoft does not specifically document "call `Trim` when a Win32 window is hidden". ([IDXGIDevice3::Trim](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_3/nf-dxgi1_3-idxgidevice3-trim))

## 9. WARP fallback

- `D3D_DRIVER_TYPE_HARDWARE` implements Direct3D in hardware and "is the primary driver that you should use in your Direct3D applications because it provides the best performance" (HAL). `D3D_DRIVER_TYPE_REFERENCE` is a slow, accurate software implementation intended for testing and debugging, not retail. `D3D_DRIVER_TYPE_NULL` has no render capability. `D3D_DRIVER_TYPE_SOFTWARE` is completely software and "not intended for a high-performance application." ([D3D_DRIVER_TYPE](https://learn.microsoft.com/en-us/windows/win32/api/d3dcommon/ne-d3dcommon-d3d_driver_type))
- `D3D_DRIVER_TYPE_WARP` is "a high-performance software rasterizer" supporting feature levels 9_1 through 10_1; the Windows 8 WARP driver supports 9_1 through 11_1, and the Windows 8.1 WARP driver fully supports 11_1 including `IDXGIDevice3::Trim`, shared BCn surfaces, minblend, and map default. ([D3D_DRIVER_TYPE](https://learn.microsoft.com/en-us/windows/win32/api/d3dcommon/ne-d3dcommon-d3d_driver_type))
- `D3D11CreateDevice` takes the driver type in its `DriverType` parameter. If `pAdapter` is non-NULL, `DriverType` must be `D3D_DRIVER_TYPE_UNKNOWN` and `Software` must be NULL; if `pAdapter` is NULL, `DriverType` cannot be `UNKNOWN`. ([D3D11CreateDevice](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-d3d11createdevice))
- `D3D11_CREATE_DEVICE_BGRA_SUPPORT` (0x20) creates a device supporting BGRA formats and is "Required for Direct2D interoperability with Direct3D resources." ([D3D11_CREATE_DEVICE_FLAG](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/ne-d3d11-d3d11_create_device_flag))
- `CreateSwapChainForComposition` excludes software drivers "like `D3D_DRIVER_TYPE_REFERENCE`" for composition swap chains; that page does not name `D3D_DRIVER_TYPE_WARP` explicitly. ([CreateSwapChainForComposition](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_2/nf-dxgi1_2-idxgifactory2-createswapchainforcomposition))
- `D3D11CreateDevice` takes a single `D3D_DRIVER_TYPE` per call; Microsoft does not document a built-in single-call multi-driver fallback. The documented inputs are the driver type plus adapter rules above, so a hardware→WARP fallback consists of separate calls with `D3D_DRIVER_TYPE_HARDWARE` and then `D3D_DRIVER_TYPE_WARP`. ([D3D11CreateDevice](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-d3d11createdevice); [D3D_DRIVER_TYPE](https://learn.microsoft.com/en-us/windows/win32/api/d3dcommon/ne-d3dcommon-d3d_driver_type))

## Facts not established by the primary sources checked

- No specific HRESULT is documented for "acrylic setup failed" or for passing an unsupported `DWMWA_*` value; only the generic `DwmSetWindowAttribute` success/failure contract and the Windows-7-era `DWM_E_COMPOSITIONDISABLED`. ([DwmSetWindowAttribute](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/nf-dwmapi-dwmsetwindowattribute))
- Microsoft does not document the Windows 11 DWM backdrop/corner attributes as supported on Windows 10; the checked reference pages give Windows 11 build numbers as their minimum. ([DWMWINDOWATTRIBUTE](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute))
